# Plain uncontrolled form + `FormData`

The simplest integration. No state library; the browser owns the values, and
`Object.fromEntries(new FormData(form))` at submit time is enough for most
non-dynamic forms.

```tsx
import {
  Form,
  FormField,
  FormLabel,
  FormControl,
  FormDescription,
  FormMessage,
  Input,
  Button,
  Stack,
} from '@arshad-shah/cynosure-react';

export function ContactForm() {
  return (
    <Form
      onSubmit={(e) => {
        e.preventDefault();
        const data = Object.fromEntries(new FormData(e.currentTarget).entries());
        fetch('/api/contact', { method: 'POST', body: JSON.stringify(data) });
      }}
    >
      <Stack gap="4">
        <FormField name="name" required>
          <FormLabel>Your name</FormLabel>
          <FormControl>
            <Input />
          </FormControl>
        </FormField>

        <FormField name="email" required>
          <FormLabel>Email</FormLabel>
          <FormControl>
            <Input type="email" />
          </FormControl>
          <FormDescription>We will never share your email.</FormDescription>
        </FormField>

        <Button type="submit">Send</Button>
      </Stack>
    </Form>
  );
}
```

## What wires up automatically

- `FormField` generates a stable `id` from `name` + `useId`.
- `FormLabel.htmlFor` is the generated id.
- `FormControl` injects `id`, `name`, `aria-describedby`, `aria-invalid`,
  `disabled`, `required`, and `invalid` onto its single child — existing
  values on the child win.
- `FormDescription` registers into `aria-describedby`.
- `FormMessage` renders nothing when its children are empty and renders with
  `role="alert"` when the field is `invalid`.

## `Form`

`<Form>` is a thin wrapper over `<form>`. It defaults `noValidate` to `true`
so the browser's native validation bubbles don't fight `FormMessage`. Pass
`noValidate={false}` to opt back in.
