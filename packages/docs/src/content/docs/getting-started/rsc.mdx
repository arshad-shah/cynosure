# Server Components & SSR

Cynosure works with **Next.js App Router**, **Remix**, and any other framework
that supports React Server Components.

## Every component ships `'use client'`

Cynosure components use hooks, refs, and (for interactive ones) state, event
handlers, portals, and Context — none of which are valid in a React **Server
Component**. So every published component entry ships the `'use client'`
directive. In practice that means:

- **You can import any component directly into a Server Component** — including
  your root `layout.tsx` or a `page.tsx` — with **no `'use client'` wrapper file
  of your own.** Next.js sees the directive and places the component in the
  client graph for you.
- Components still **server-render (SSR) and hydrate** normally. "Client
  component" means it ships a little JS and hydrates — not that it's skipped on
  the server.
- Only **your own** components that use state/hooks/handlers still need their own
  `'use client'` — that's a rule about your code, not Cynosure's.

> Trade-off: because structural primitives (`Box`, `Text`, `Card`, …) are client
> components, they ship their (tiny) JS to the browser rather than rendering to
> zero-JS server markup. We consider that a fair price for "import anything,
> anywhere, with no boundary to manage" — and the per-component JS is a few
> hundred bytes.

## Setup (Next.js App Router)

`CynosureProvider` holds app-wide Context (theme, direction, locale, tooltip
timing) and **loads the design tokens**, so mount it once near the root. It's a
client component (it ships `'use client'`), and the cleanest place for it is a
small `providers.tsx`:

```tsx
// app/providers.tsx
'use client';
import { CynosureProvider } from '@arshad-shah/cynosure-react';

export function Providers({ children }: { children: React.ReactNode }) {
  return <CynosureProvider>{children}</CynosureProvider>;
}
```

```tsx
// app/layout.tsx  —  stays a Server Component, no CSS import needed
import { Providers } from './providers';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

There's **no stylesheet import** in `layout.tsx`: `CynosureProvider` loads the
design tokens, and each component's CSS auto-loads when you import the component.

## Patterns

### Use components directly in a Server Component

No wrapper file required — import and render:

```tsx
// app/page.tsx  —  Server Component
import { Card } from '@arshad-shah/cynosure-react/card';
import { Heading } from '@arshad-shah/cynosure-react/heading';
import { Text } from '@arshad-shah/cynosure-react/text';
import { Stack } from '@arshad-shah/cynosure-react/stack';

export default async function Page() {
  const data = await fetchData(); // safe server-side work
  return (
    <Card>
      <Stack gap="2">
        <Heading>{data.title}</Heading>
        <Text>{data.body}</Text>
      </Stack>
    </Card>
  );
}
```

### Your own stateful code still needs `'use client'`

The directive Cynosure ships covers *its* components. A component **you** write
that holds state or handlers is a client component and needs its own directive:

```tsx
// app/contact-form.tsx
'use client';
import { useState } from 'react';
import { Form, FormField } from '@arshad-shah/cynosure-react/form';
import { Input } from '@arshad-shah/cynosure-react/input';
import { Button } from '@arshad-shah/cynosure-react/button';

export function ContactForm() {
  const [value, setValue] = useState('');
  // …
}
```

## Streaming, Suspense & `loading.tsx`

Cynosure components are pure with respect to render output — no module-level side
effects, no `typeof window` branching at render, no `localStorage` access outside
`useEffect`. You can suspend at any point and use `<Skeleton>` / `<Spinner>`
inside `loading.tsx` without warnings.

## React 18 vs React 19

Cynosure supports **React 18 and 19**. RSC works on both — Next.js 13 / 14
(React 18) and Next.js 15 (React 19) are equally supported.

## FAQ

**Do I need a `'use client'` wrapper to use a Cynosure component in a Server Component?**
No. Every Cynosure component already ships the directive, so you can import and
render it directly in a Server Component.

**Do I need `suppressHydrationWarning` on `<html>`?**
Only if you toggle themes before hydration via the theme init script. The
attribute change is intentional and React would otherwise warn.

**Can I import from a sub-path inside a Server Component?**
Yes — `import { Card } from '@arshad-shah/cynosure-react/card'` works identically
and keeps the bundle smaller for that leaf. Prefer sub-path imports.

**Do I still need to import a stylesheet?**
No — mounting `CynosureProvider` loads the design tokens, and component CSS
auto-loads on import. (Provider-less or non-React surfaces can import
`@arshad-shah/cynosure-react/all.css` or `@arshad-shah/cynosure-tokens/css`
manually.)
