# Installation

## Zero-config

<PackageManagerTabs command="@arshad-shah/cynosure-cli init" kind="dlx" />

Detects your framework (Next.js App Router, Next.js Pages, Vite, CRA, Remix),
prints the exact install command for your package manager, and wires up
`CynosureProvider` (for the Next.js App Router it also scaffolds a
`providers.tsx`). There's **no CSS import to wire** — the provider loads the
design tokens and each component's CSS auto-loads on import. Add `--dry-run` to
preview.

## Requirements

- Node 22 or newer for local development (Cynosure is authored against ESM and
  uses native TypeScript loading).
- **React 18 or 19** (peer dependency). Works with Next.js 13 / 14 / 15, Vite,
  CRA, and Remix.

## Styling: nothing to import

Cynosure splits styling into two layers, and both load themselves:

- **Design tokens** — the global `:root { --cynosure-* }` custom properties
  (light + dark) that every component reads. These are loaded for you by
  **`CynosureProvider`** (see [Wrap your app](#wrap-your-app)). Mount the
  provider once and the tokens are present app-wide — no stylesheet import.
- **Component CSS** — each component's own rules. Every per-component JS entry
  prepends its CSS imports, so your bundler wires them up automatically when you
  `import { Button } from '@arshad-shah/cynosure-react/button'`. See
  [Per-component CSS](#per-component-css).

So the happy path is: **install → wrap in `CynosureProvider` → import components.**
No `all.css`, no manual token import.

### When you still need a manual CSS import

Import the tokens yourself only when there's **no `CynosureProvider`** in the
tree — e.g. plain HTML, email, a non-React surface, or a component rendered
outside the provider. Either grab the all-in-one bundle:

```ts
import '@arshad-shah/cynosure-react/all.css'; // tokens (light + dark) + every component's CSS
```

…or just the tokens (component CSS still auto-loads per import):

```ts
import '@arshad-shah/cynosure-tokens/css';      // design tokens, light
import '@arshad-shah/cynosure-tokens/css/dark';  // dark overrides
```

In development the provider warns in the console if it can't find the tokens at
runtime, so a misconfigured bundler won't fail silently.

### Webfonts (optional)

The default token font stacks resolve to **Geist Variable** (sans) and
**JetBrains Mono Variable** (mono), falling through to system fonts when those
families aren't loaded. Add one more import to bundle them:

```ts
import '@arshad-shah/cynosure-react/fonts.css';
```

Kept separate from `all.css` so you don't pay the ~400 KB woff2 cost if you
have your own font pipeline (`next/font`, self-hosted, CDN). With `next/font`,
skip this import and override `--cynosure-font-family-sans` / `-mono` with
your font's CSS variable.

### Per-component CSS

If you import per-component, your bundler wires up the CSS automatically:

```ts
import { Button } from '@arshad-shah/cynosure-react/button';
```

Every per-component JS entry prepends its CSS imports, so subpath imports
never need a manual stylesheet include. Each component imports `core.css`
(the universal scaffolding — the layout-prop `@property` declarations and
the body reset) followed by only the shared chunks under `shared/` that it
participates in, then its own rules. Shared rules are split by which
components use them, so a single-component import pulls just that
component's CSS (~1.5–3 kB brotli) rather than the whole shared baseline —
and importing many components still deduplicates each chunk to one copy.

If you're code-splitting and want to preload the universal scaffolding
yourself, it's reachable directly:

```ts
import '@arshad-shah/cynosure-react/core.css';
```

## Wrap your app

`CynosureProvider` composes `ThemeProvider`, `DirectionProvider`, `LocaleProvider`, and the global `TooltipProvider` in a single wrapper — and **loads the design tokens** so you don't import any stylesheet:

```tsx
import { CynosureProvider } from '@arshad-shah/cynosure-react';

<CynosureProvider theme={{ defaultTheme: 'system' }}>
  <App />
</CynosureProvider>
```

Everything is optional — pass only what you want to override. The individual
providers are still exported if you prefer to compose them yourself.

## Framework-specific setup

### Next.js App Router

Create a `providers.tsx` client boundary to wrap the server root layout:

```tsx
// app/providers.tsx
'use client';
import { CynosureProvider } from '@arshad-shah/cynosure-react';

export function Providers({ children }: { children: React.ReactNode }) {
  return <CynosureProvider>{children}</CynosureProvider>;
}
```

```tsx
// app/layout.tsx — no CSS import; <Providers> loads the tokens
import { Providers } from './providers';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

### Next.js Pages Router

```tsx
// pages/_app.tsx
import type { AppProps } from 'next/app';
import { CynosureProvider } from '@arshad-shah/cynosure-react';

export default function MyApp({ Component, pageProps }: AppProps) {
  return (
    <CynosureProvider>
      <Component {...pageProps} />
    </CynosureProvider>
  );
}
```

### Vite

```tsx
// src/main.tsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import { CynosureProvider } from '@arshad-shah/cynosure-react';
import App from './App';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <CynosureProvider>
      <App />
    </CynosureProvider>
  </React.StrictMode>,
);
```

### Remix

```tsx
// app/root.tsx
import { CynosureProvider } from '@arshad-shah/cynosure-react';
import { Outlet } from '@remix-run/react';

export default function App() {
  return (
    <CynosureProvider>
      <Outlet />
    </CynosureProvider>
  );
}
```

### Create React App

```tsx
// src/index.tsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import { CynosureProvider } from '@arshad-shah/cynosure-react';
import App from './App';

ReactDOM.createRoot(document.getElementById('root') as HTMLElement).render(
  <React.StrictMode>
    <CynosureProvider>
      <App />
    </CynosureProvider>
  </React.StrictMode>,
);
```

## TypeScript

Cynosure is authored in TypeScript and publishes types with full JSDoc. If you
use `skipLibCheck: false`, make sure your `lib` includes `DOM` and `DOM.Iterable`.
