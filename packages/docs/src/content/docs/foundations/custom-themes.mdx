# Authoring a custom theme

The easiest way to build a theme is **`defineTheme`** — a typed helper. You
describe the tokens you want to change as a plain object; your editor
autocompletes every overridable slot, a typo is a *compile error* (not a
silently-ignored CSS property), and the result drops straight into
`CynosureProvider` with no separate stylesheet to import or wire up.

## `defineTheme` — the typed way

```tsx
import { CynosureProvider, defineTheme } from '@arshad-shah/cynosure-react';

const ocean = defineTheme(
  'ocean',
  {
    color: {
      accent: { solid: '#0ea5e9', solidHover: '#0284c7', onSolid: '#ffffff' },
      background: { canvas: '#0b1220', surface: '#0f1b2d' },
      foreground: { default: '#e2e8f0', muted: '#94a3b8' },
      border: { default: '#1e293b' },
    },
    radius: { component: { md: '10px' } },
  },
  { colorScheme: 'dark' }, // sets the root color-scheme for native controls
);

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <CynosureProvider theme={{ customThemes: [ocean], defaultTheme: 'ocean' }}>
      {children}
    </CynosureProvider>
  );
}
```

That's the whole setup. Passing the theme via `customThemes`:

- **injects its CSS as a server-rendered `<style>`** — styled on first paint, no
  flash, SSR-safe;
- **registers the name** automatically, so `setTheme('ocean')` (and persistence)
  just work — no need to also list it in `themes`;
- **applies the declared `colorScheme`**, so native form controls, scrollbars,
  and `prefers-color-scheme`-derived UA styling match.

You only override what differs — every other token cascades from the base
`:root`, so a polished theme is often just a handful of colours. The token shape
mirrors the [design tokens](/foundations/design-tokens) exactly: `color.*`,
`radius.*`, `shadow.*`, `space.*`, and so on. Let autocomplete guide you.

### It's just data

`defineTheme` returns `{ name, colorScheme, css }`. If you'd rather not inject at
runtime, write the generated CSS to a file at build time:

```ts
import { writeFileSync } from 'node:fs';
writeFileSync('ocean.css', ocean.css); // [data-theme="ocean"]{ … }
```

…and import that `.css` yourself. Same output, your choice of delivery.

## Toggling themes

Any registered theme — built-in or custom — switches at runtime via `useTheme`:

```tsx
import { useTheme } from '@arshad-shah/cynosure-react';

function ThemeMenu() {
  const { theme, themes, setTheme } = useTheme();
  return (
    <select value={theme} onChange={(e) => setTheme(e.target.value)}>
      {themes.map((name) => (
        <option key={name} value={name}>{name}</option>
      ))}
    </select>
  );
}
```

## Scope to a subtree, not the whole page

`CynosureProvider` activates the theme by setting `data-theme` on `<html>`. To
theme just one container (a preview pane, an embedded widget), set `data-theme`
on any element — the custom-property cascade handles the rest:

```tsx
<div data-theme="ocean">
  {/* renders with the ocean palette */}
</div>
```

(The `ocean` theme's `<style>` still needs to be present — keep it in
`customThemes` on the provider, or import its `.css`.)

## Advanced: hand-authored CSS

`defineTheme` is a thin wrapper over the underlying contract: **a theme is just
a `[data-theme="name"]` block that overrides `--cynosure-*` custom properties.**
If you're shipping a theme as a standalone CSS package (no React, no provider),
write it directly:

```css
[data-theme='brand'] {
  /* Accent — buttons, links, focus rings */
  --cynosure-color-accent-solid: #0f766e;
  --cynosure-color-accent-solid-hover: #115e59;
  --cynosure-color-accent-on-solid: #ffffff;

  /* Surfaces & foreground */
  --cynosure-color-background-canvas: #f6fbfa;
  --cynosure-color-background-surface: #ffffff;
  --cynosure-color-foreground-default: #042f2e;
  --cynosure-color-foreground-muted: #134e4a;
  --cynosure-color-border-default: #d6e4e1;

  color-scheme: light;
}
```

Use the exact token names from the [design-tokens reference](/foundations/design-tokens)
— that's precisely the lookup `defineTheme` does for you. Ship it as a
side-effect CSS export and let consumers `import 'my-brand-theme/cynosure'`, then
add `'brand'` to `ThemeProvider`'s `themes`.

## Testing a custom theme

Cynosure ships a contrast audit that walks compiled CSS and asserts WCAG 2.1 AA
pairs. Add your theme to `scripts/audit-contrast.mjs` to run it in CI:

```bash
pnpm audit:contrast
```
