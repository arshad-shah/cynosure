# Menu

A button that opens a list of commands: edit, copy, export, delete. Choosing one runs it and closes the menu. For picking a value that stays shown on the control, use [Select](?path=/docs/components-select--docs).

<Canvas of={Stories.KeyboardOpensNavigatesAndSelects} />

## When to use

- **Overflow actions** for an item (a row's "more" button) or a toolbar.
- **Several related commands** that don't each deserve a visible button.
- **View options** with checkable items (`kind: "checkbox"` toggles, `kind: "radio"` picks one of a set).

**Use something else when:**
- the user picks a value for a form: [Select](?path=/docs/components-select--docs)
- there are only one or two actions: show [Button](?path=/docs/components-button--docs)s
- the panel holds controls or a form: [Popover](?path=/docs/components-popover--docs)
- the items navigate to pages: links in your navigation

## Usage

```tsx
import { IconButton, Menu } from "@arshad-shah/cynosure";
import { copy, edit, moreHorizontal, trash } from "@arshad-shah/cynosure/icons";

<Menu
  label="File actions"
  trigger={(props) => <IconButton {...props} icon={moreHorizontal} label="More actions" />}
  items={[
    { value: "edit", label: "Edit", icon: edit, shortcut: ["Ctrl", "E"] },
    { value: "copy", label: "Copy path", icon: copy },
    { label: "Danger zone", items: [{ value: "delete", label: "Delete", icon: trash, tone: "danger" }] },
  ]}
  onSelect={(value) => run(value)}
/>
```

`trigger` is a render prop: spread its props onto a [Button](?path=/docs/components-button--docs) or [IconButton](?path=/docs/components-iconbutton--docs). Sections (`{ label, items }`) render as a named group after a separator.

## Checkable items

Checkable items keep the menu open, so several options can be changed in one go. Keep `checked` in your state and update it in `onSelect`.

<Canvas of={Stories.CheckableItemsStayOpen} />

## Coloured icons

Item icons are muted by default. `iconTone` and `iconColor` colour one item's icon and mean what [Icon](?path=/docs/foundations-icon--docs)'s `tone` and `color` mean: `iconTone` is a semantic colour (`accent`, `neutral`, `danger`, `success`, `warning`, `info`, `muted`), `iconColor` is any CSS colour and overrides it (`brand` draws a brand mark in its owner's colour). The highlighted item keeps the colour and a disabled item shows its icon muted.

## Props

<ArgTypes of={Stories} />

Item fields: `value`, `label`, `icon`, `iconTone`, `iconColor`, `shortcut` (keys such as `["Ctrl", "E"]`), `disabled`, `tone` (`neutral` or `danger`), `kind` (`checkbox` or `radio`) and `checked`.

## Behaviour and accessibility

| Input | Result |
| --- | --- |
| <kbd>Enter</kbd>, <kbd>Space</kbd>, click or <kbd>Down</kbd> arrow on the trigger | Opens on the first item |
| <kbd>Up</kbd> arrow on the trigger | Opens on the last item |
| <kbd>Down</kbd> / <kbd>Up</kbd> arrows, <kbd>Home</kbd>, <kbd>End</kbd> | Move between items, wrapping and skipping disabled ones |
| A letter | Jumps to the next item starting with it |
| <kbd>Enter</kbd>, <kbd>Space</kbd>, click | Runs the item and closes (checkable items stay open) |
| <kbd>Escape</kbd> | Closes and returns focus to the trigger |
| <kbd>Tab</kbd> | Closes and moves on to the next control |

- **Roles:** `menu` named by `label`, items as `menuitem`, `menuitemcheckbox` or `menuitemradio` with `aria-checked`, sections as named `group`s.
- **Shortcuts** are shown with [Kbd](?path=/docs/components-kbd--docs) and announced through `aria-keyshortcuts`. The menu shows them; your app still has to handle the keys.
- **Disabled items** stay visible (so people learn the command exists) but can't be focused or run.
- **Layers:** inside a [Popover](?path=/docs/components-popover--docs) or dialog, Escape closes only the menu.

## Touch

Rows are at least 44px tall on coarse pointers, and a tap runs the item.

## Theming

Tokens: `--cy-menu-min-width`, `--cy-menu-max-width`, `--cy-menu-radius` and `--cy-menu-row-height`.

```ts
createTheme({ components: { menu: { minWidth: "240px", radius: "10px" } } });
```
