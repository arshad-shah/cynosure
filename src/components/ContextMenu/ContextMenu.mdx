# ContextMenu

A menu of commands for one thing, opened where the person points: right-click with a mouse, a long press on a touch screen, or Shift+F10 on the keyboard.

<Canvas of={Stories.RightClickOpensWhereYouPoint} />

## When to use

- **Shortcuts on an item**: a file row, a card, a node in a canvas or tree.

**Use something else when:**
- the commands have a visible button: [Menu](?path=/docs/components-overlays-menu--docs). A context menu is hidden, so every command in it must also be reachable another way.
- the commands apply to the whole app: [CommandPalette](?path=/docs/components-overlays-commandpalette--docs)

## Usage

`children` is a function: spread the props it receives onto one element, and make that element focusable so keyboard users can open the menu.

```tsx
import { ContextMenu } from "@arshad-shah/cynosure";

<ContextMenu label="File actions" items={items} onSelect={run}>
  {(props) => (
    <div {...props} tabIndex={0}>
      report.pdf
    </div>
  )}
</ContextMenu>
```

Items are the same as [Menu](?path=/docs/components-overlays-menu--docs)'s: icons, shortcuts, sections (labelled, or separated by lines only), submenus (an item with `items`; Right arrow, Enter or a click opens one, Left or Escape closes it, and choosing in one closes the whole menu), disabled, danger and checkable items.

## Many targets

For the rows of a list or the tabs of a tab list, use one ContextMenu for all of them: spread `targetFor(key)` (the render prop's second argument) onto each, with a key such as the row's item. `label` and `items` may then be functions of that key, and `onSelect` and `onOpenChange` receive it after the value. The menu sits beside the list, not in it, so a list that may hold only its own items (a tablist, a tree) stays valid, and focus returns to the target that opened it. Tabs and Tree host their context menus this way.

```tsx
<ContextMenu<File>
  label={(file) => `${file.name} actions`}
  items={(file) => commandsFor(file)}
  onSelect={(command, file) => run(command, file)}
>
  {(_, targetFor) => files.map((file) => <li key={file.id} {...targetFor(file)} tabIndex={0}>{file.name}</li>)}
</ContextMenu>
```

## Opened by the app, at a point

Things drawn on a canvas have no element each to spread target props onto. The app finds the object itself (the one under a right-click, or the selected one for Shift+F10) and opens the menu for it: `open` controls it, `anchor` places it at a point (`{ x, y }` in client coordinates, such as the event's `clientX` and `clientY`; or any element or virtual anchor), and `label` and `items` are the ones for that object. `onOpenChange(false)` reports Escape, a choice, Tab or an outside press. Focus returns to what had it when the menu opened (the canvas). `children` is optional here; with a target as well, a menu the app opens without `anchor` sits under the target, and a right-click asks to open through `onOpenChange(true)`.

```tsx
const [menu, setMenu] = useState<{ shape: Shape; x: number; y: number } | null>(null);

<canvas
  onContextMenu={(e) => {
    const shape = shapeAt(e.clientX, e.clientY);
    if (!shape) return;
    e.preventDefault();
    setMenu({ shape, x: e.clientX, y: e.clientY });
  }}
/>
<ContextMenu
  open={menu !== null}
  anchor={menu ?? undefined}
  onOpenChange={(open) => !open && setMenu(null)}
  label={menu ? `${menu.shape.name} actions` : ""}
  items={shapeCommands}
  onSelect={(command) => run(command, menu?.shape)}
/>
```

## Coloured icons

Because the item type is Menu's, `iconTone` and `iconColor` colour an item's icon here as well, with the meaning of [Icon](?path=/docs/foundations-icon--docs)'s `tone` and `color`. Icons without them stay muted, and a disabled item shows its icon muted.

## Behaviour and accessibility

| Input                          | Action                                                    |
| ------------------------------ | --------------------------------------------------------- |
| Right-click                    | Opens with the menu's corner at the pointer               |
| Shift+F10 / context menu key   | Opens under the focused target                            |
| Long press (500ms) on touch    | Opens at the finger; a tap or a scroll does not           |
| Arrow keys, Home, End, letters | Move through items (as in Menu)                           |
| Enter / Space                  | Run the item and close                                    |
| Escape, Tab, click outside     | Close; focus returns to the target (or, opened by the app, to what had focus) |

- The target gets `aria-keyshortcuts="Shift+F10"`. Mention the menu in the target's description if it holds commands found nowhere else.
- Near the edges of the window the menu flips to stay on screen.
- With `disabled`, the browser's own menu shows.
- On touch screens, add `-webkit-touch-callout: none` and `user-select: none` to the target so the system callout does not compete with the menu.
