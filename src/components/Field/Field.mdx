# Field

Adds a label, help text and an error message to any control and wires them together for assistive tech. Your control is rendered through a render prop that receives the ids and state. Checkbox and Switch carry their own label, so they don't need Field.

<Canvas of={Stories.LabelAndDescription} />

## When to use

- Around a text input, select or any custom control that needs a visible label.
- To show validation errors consistently.
- With `group` to label a set of controls such as a radio group.

**Use something else when:**
- the control brings its own label: [Checkbox](?path=/docs/components-checkbox--docs)
- the component already includes a Field, such as [TextField](?path=/docs/components-textfield--docs)

## Usage

```tsx
import { Field, InputBase } from "@arshad-shah/cynosure";

<Field label="Email" description="We never share it." error={error} required>
  {(f) => <InputBase id={f.id} aria-describedby={f.describedBy} invalid={f.invalid} required />}
</Field>
```

The render prop gives you `id`, `describedBy` and `invalid`. Pass them to the control.

## Errors and required

`error` is shown below the control, announced with `role="alert"`, linked to the control and marks it invalid. `required` draws the marker as a shape, not a typed asterisk; also pass `required` to the control itself.

## Settings rows

`layout="split"` puts the label and description at the start and the control at the end of one row, centred on the text, as in a settings page. When the field is too narrow for both, the control moves under the text. `width` gives the control one of three widths (or the whole field), so a column of settings lines up whatever the labels. Labels, descriptions and errors stay linked to the control. TextField and Select take both props too.

```tsx
<Field layout="split" width="md" label="Font" description="Used in the query editor.">
  {(f) => <InputBase id={f.id} aria-describedby={f.describedBy} />}
</Field>
<Select layout="split" width="md" label="Theme" description="Light, dark or the system's." options={themes} />
```

## Behaviour and accessibility

- **Label:** a `label` linked to the control, or the group label when `group` is set.
- **Hidden label:** `labelHidden` keeps the label for assistive tech but takes no space. Prefer visible labels.
- **Description and error:** linked through `aria-describedby`. The error also announces itself.
- **Size:** `sm`, `md` (default) or `lg`.
- **Split layout:** the order in the page stays label, description, control, then error, so screen readers and the Tab key meet them as in the stacked layout. Right-to-left text mirrors the row.

## Theming

Tokens: `--cy-field-gap`, `--cy-field-label-weight`, `--cy-field-label-color`, `--cy-field-description-color`, `--cy-field-error-color` and `--cy-field-required-color`. Control widths: `--cy-field-control-width-sm`, `-md` and `-lg` (160, 256 and 384px). The split layout keeps the text at least `--cy-field-split-text-min` (192px) wide before the control moves under it.

```ts
createTheme({ components: { field: { gap: "8px", labelWeight: "600" } } });
```

`className` and `style` are for layout only.
