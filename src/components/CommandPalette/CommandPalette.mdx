# CommandPalette

A search box over every command in the product. Press Ctrl+K (Command+K on a Mac), type a few letters, press Enter. It is the fastest way to reach an action without hunting through menus.

<Canvas of={Stories.KeywordsGroupsAndWrappingArrows} />

## When to use

- **Products with many actions** spread across menus and panels: inspectors, editors, database tools.

**Use something else when:**
- the actions belong to one button: a [Menu](?path=/docs/components-overlays-menu--docs)
- people pick a value for a field: a [Combobox](?path=/docs/components-controls-combobox--docs)

## Usage

```tsx
import { CommandPalette } from "@arshad-shah/cynosure";

<CommandPalette
  commands={[
    { id: "save", label: "Save file", group: "File", shortcut: ["Ctrl", "S"], keywords: ["write", "disk"] },
    { id: "preview", label: "Toggle preview", group: "View" },
  ]}
  onRun={(id) => actions[id]()}
/>
```

Mount it once near the root. It listens for its shortcut (`mod+k` by default) anywhere on the page, shadow roots included. A command's `shortcut` is only shown in the row; bind those keys with `useHotkey`.

## Finding commands

Every typed word must appear in the label or the `keywords`, in any order, and commands whose label starts with the first word come first. Each typed word is marked where it appears in a label ([HighlightedText](?path=/docs/components-feedback-and-display-highlightedtext--docs)); the option is still named by its whole label. Before anything is typed, the commands run most recently come first under "Recent".

<Canvas of={Stories.RecentCommandsComeFirst} />

Before anything is typed, commands are listed under their `group` headings. Search results are one flat list in rank order, so each row shows its group as a small [Badge](?path=/docs/components-feedback-and-display-badge--docs) between the label and the shortcut; recent commands, which mix groups, carry the tag too.

<Canvas of={Stories.SearchResultsAreFlatWithCategoryTags} />

## Your own search

`filter(command, query)` replaces the built-in search, for an app with its own fuzzy matcher. It is called for each command while there is a query (trimmed), and answers with a match, `true`, or `null`:

```tsx
<CommandPalette commands={commands} onRun={run} filter={(command, query) => fuzzyMatch(query, command.label)} />
```

- **A match** `{ score, positions }` keeps the command. Lower scores come first, as fuzzy matchers score them; ties, and matches without a score, keep the order of `commands`. `positions` are the indices of the matched characters in the label, and exactly those are marked.
- **`true`** keeps the command, unmarked. **`null`** or **`false`** leaves it out.

<Canvas of={Stories.CustomFilterRanksAndMarksItsPositions} />

## Commands made from the query

`onQueryChange(query)` hears every change of the search text (and `""` each time the palette opens). Build commands from it and pass them in `commands`, such as "Go to line 42" for a number; a custom `filter` decides whether they show. The active command stays the same while the list changes under it, if it is still there.

<Canvas of={Stories.CommandsBuiltFromTheQuery} />

## Recent commands between visits

Recently run commands live in the palette's state. `recentKey` keeps them between visits, in localStorage by default (as JSON ids, newest first, at most 20), or in any `{ get, set }` storage, sync or async, given as `recentStorage` (`chrome.storage` in an extension). It is read after mount and written when a command runs; storage that throws or is missing is ignored, and ids that no command has any more are skipped. To hold the list yourself, pass `recent` and `onRecentChange`.

```tsx
<CommandPalette commands={commands} onRun={run} recentKey="app:recent-commands" />
```

<Canvas of={Stories.RecentCommandsPersistUnderAKey} />

## Saying why a command is disabled

`disabledReason` on a `disabled` command says why it cannot run. The reason is shown in its row and is the option's description, and the arrows reach it (a disabled command without a reason is skipped), so a screen reader reads it with the command. Enter or a click runs nothing and announces `labels.unavailable(label, reason)` ("Export as PDF is unavailable: Open a document first").

## Shortcuts with useHotkey

```tsx
import { useHotkey } from "@arshad-shah/cynosure";

useHotkey("mod+s", save);
useHotkey("/", focusSearch); // plain keys are ignored while typing in a field
```

Shortcuts with Ctrl, Command or Alt work everywhere, text fields included. Plain keys are ignored in fields, so "/" still types a slash. Add `data-cy-hotkeys="off"` to a subtree (a code editor with its own bindings) to opt it out.

## Behaviour and accessibility

| Input | Result |
| --- | --- |
| <kbd>Ctrl</kbd> / <kbd>Command</kbd> + <kbd>K</kbd> | Opens or closes it from anywhere |
| Typing | Filters the commands into one flat list, each tagged with its group |
| <kbd>Down</kbd> / <kbd>Up</kbd> | Next / previous command, wrapping around; disabled ones are skipped unless they have a `disabledReason` |
| <kbd>Enter</kbd> or a click | Runs the command and closes; on a disabled command with a reason, announces the reason |
| <kbd>Escape</kbd> or the backdrop | Closes; focus returns to where it was |

- **Roles:** a modal `dialog` named by `labels.title`, holding a `combobox` search field and a `listbox` of `option`s in named `group`s (search results are one unnamed group). A row's group tag is part of its name. The active command is `aria-activedescendant`, so focus stays in the search field.
- **Fresh each time:** the search field is empty whenever it opens.
- **Shadow DOM:** works inside shadow roots (extensions), including the shortcut.

## Touch

Command rows are at least 44px tall on coarse pointers. On narrow screens the panel spans the width.

## Theming

Tokens: `--cy-command-palette-width`, `--cy-command-palette-offset` (distance from the top) and `--cy-command-palette-list-max-height`. The backdrop uses `--cy-dialog-scrim`.
