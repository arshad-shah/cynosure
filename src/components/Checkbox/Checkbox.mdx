# Checkbox

A checkbox with a label, for choices that are independent of each other. It is a native input under a drawn box, so forms, reset and keyboard work as the browser does them. For a setting that takes effect immediately, use [Switch](?path=/docs/components-controls-switch--docs).

<Canvas of={Stories.CheckedShowsMark} />

## When to use

- Several options where any number can be on.
- A single agreement or preference saved with a form.
- A "select all" row with `indeterminate` when only some items are chosen.
- A list of tasks, with `strikeWhenChecked` so a finished task reads as done.
- A grid of pictures to tick (the pages of a document), with `variant="card"` and `media`.

**Use something else when:**
- the change applies immediately: [Switch](?path=/docs/components-controls-switch--docs)
- exactly one option may be chosen: [RadioGroup](?path=/docs/components-controls-radiogroup--docs)
- it triggers an action: [Button](?path=/docs/components-controls-button--docs)

## Usage

```tsx
import { Checkbox } from "@arshad-shah/cynosure";

<Checkbox label="Email me updates" name="updates" value="yes" />
<Checkbox label="Select all" checked={all} indeterminate={some} onChange={toggleAll} />
<Checkbox label="Remember me" description="Keeps you signed in on this device." defaultChecked />
<Checkbox label="Buy oat milk" strikeWhenChecked checked={done} onChange={setDone} />
```

`onChange` receives the new `checked` boolean. Use `checked` for controlled and `defaultChecked` for uncontrolled. `name`, `value`, `required` and `disabled` are passed to the native input.

## Label and description

`label` is required. An optional `description` sits below it and is linked with `aria-describedby`. `size` is `sm`, `md` or `lg` and `tone` sets the fill when checked (default `accent`).

## Indeterminate

`indeterminate` shows a dash and is announced as "mixed". It is a display state only: you decide what the next click does.

<Canvas of={Stories.IndeterminateIsMixed} />

## Checklists

`strikeWhenChecked` strikes through and mutes the label while the box is checked, and mutes the description with it. It works the same controlled or uncontrolled. A box that is `indeterminate` is not struck: a partly done task is not done.

<Canvas of={Stories.StrikeWhenCheckedByPointerAndKeyboard} />

The muted label keeps a contrast of at least 4.5:1 against the surface in light and dark.

## Cards

`variant="card"` draws a bordered card with `media` above the label. The whole card, picture included, ticks the box, which stays drawn over the picture's top end corner; a ticked card has the accent border and soft background. The label names the checkbox, not the picture. `onChange(checked, event)` is unchanged, so a Shift+click on a picture still reads `event.nativeEvent.shiftKey` for range selection. Lay cards out with [Grid](?path=/docs/components-structure-grid--docs).

```tsx
<Grid columns={4}>
  {pages.map((p) => (
    <Checkbox
      key={p.number}
      variant="card"
      media={<Image src={p.thumbnail} alt="" />}
      label={`Page ${p.number}`}
      checked={chosen.has(p.number)}
      onChange={(on, event) => pick(p.number, on, event.nativeEvent.shiftKey)}
    />
  ))}
</Grid>
```

## Behaviour and accessibility

| Input | Result |
| --- | --- |
| Click or tap the box or label (a card's picture too) | Toggles |
| <kbd>Space</kbd> | Toggles |
| <kbd>Tab</kbd> | Focus with a visible ring |

- **Forms:** values reach `FormData`, form reset restores the initial state, and `required` is enforced by the browser.
- **Whole row:** the label and description are part of the click target.
- **Named and described from outside:** `aria-labelledby` names the input by other elements (a column heading) instead of its label; pair it with `labelHidden`, which keeps the label for assistive tech but takes no space. Your `aria-describedby` ids are read before the description.
- **Roving focus:** `tabIndex={-1}` reaches the input, for a grid or list that moves focus itself.
- **The change event:** `onChange(checked, event)`. The event's `nativeEvent` is the click that toggled the input, so `event.nativeEvent.shiftKey` tells a Shift+click (select a range of rows) from a plain one.

<Canvas of={Stories.ShiftClickAndRovingTabIndex} />

- **Done style:** with `strikeWhenChecked` the checked state is still what is announced; the strike only shows it. In forced colours the muted colour is dropped and the strike stays, in the system text colour. The colour change is a transition and is switched off under reduced motion.

## Touch

The hit area is at least 24px, growing to 44px on coarse pointers without changing the visible size.

## Theming

Tokens: `--cy-checkbox-size`, `--cy-checkbox-radius` and `--cy-checkbox-border`. The `sm` and `lg` sizes use `--cy-checkbox-size-sm` and `--cy-checkbox-size-lg` (`sizeSm` and `sizeLg` in `createTheme`; default 14px and 20px), which RadioGroup's circles read too.

| Token | Controls |
| --- | --- |
| `--cy-checkbox-done-color` | Label and description colour of a checked `strikeWhenChecked` row. Default `--cy-color-muted`. Keep it at 4.5:1 or more against the surface. |
| `--cy-checkbox-strike-width` | Thickness of the strike. Default: the border width, or 1/16 of the text size when that is larger. |

The row around the box is a [Choice](?path=/docs/components-controls-choice--docs): the space between box and label is `--cy-choice-gap`, and the two done tokens above become the row's `--cy-choice-done-color` and `--cy-choice-strike-width`.

```ts
createTheme({ components: { checkbox: { radius: "50%" } } });
```
