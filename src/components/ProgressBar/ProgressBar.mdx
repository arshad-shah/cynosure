# ProgressBar

Shows how far a task has got: an upload, an export, the steps of a setup. When the amount is unknown it shows a moving segment instead.

<Canvas of={Stories.ReportsItsValue} />

## When to use

- **A task with a measurable amount** (bytes, files, steps) that takes long enough to watch.
- **A task in progress whose length is unknown**, shown in place of the result: `indeterminate`.

**Use something else when:**
- the wait is short and inside a button: the Button's `loading` state
- a small inline busy indicator is enough: [LoadingDots](?path=/docs/components-feedback-and-display-loadingdots--docs)
- the person sets the value: a Slider

## Usage

```tsx
import { ProgressBar } from "@arshad-shah/cynosure";

<ProgressBar label="Uploading 3 files" value={uploaded} max={total} showValue />
<ProgressBar label="Preparing export" indeterminate />
```

Leave `value` out (or pass `indeterminate`) while the amount is unknown, then pass it once you know it. Values outside 0…`max` are clamped.

<Canvas of={Stories.Indeterminate} />

## Value text

By default the value reads as a percentage. Pass `labels.value` to describe it in your own words; the same text is shown with `showValue` and read by screen readers.

<Canvas of={Stories.LabelsAndHiddenLabel} />

## Meters and steps

A progress bar says how far a task has got. A **meter** measures something that is not a task: password strength, entropy, a quota. Set `meter` and the bar becomes `role="meter"`; it always has a value (a missing one reads 0) and never sweeps. Give the value in words with `valueText` ("Strong", "62 bits"): it is shown with `showValue` and read out instead of the percentage.

`steps` draws the track as separate pills, lit up to round(value / max times steps), for a stepped gauge. Pick the `tone` from the value: the lit pills take it, the rest stay the track colour. Steps work on a progress bar too ("Step 2 of 5").

```tsx
<ProgressBar label="Password strength" meter steps={4} max={4} value={score} valueText="Good" tone="success" showValue />
<ProgressBar label="Entropy" meter max={128} value={62} valueText="62 bits" tone="warning" showValue />
```

<Canvas of={Stories.StepsLightUpToTheValue} />

## Segments and markers

`segments` draws parts end to end instead of one fill, starting at `offset` (in the same units as `max`): a request's timing (DNS, connect, wait, download) or a waterfall row. Each part has a `label`, read out with its value ("DNS 12, Connect 30"), and a `tone` or a category `color` (any CSS colour); a part with neither takes the bar's `tone`. `marker` draws a thin mark across the track at a value, such as a budget or a target, read with the value as `markerLabel` (default "marker at 75%").

```tsx
<ProgressBar
  label="Request timing"
  max={200}
  offset={20}
  marker={150}
  markerLabel="budget 150 ms"
  segments={[
    { value: 12, label: "DNS", tone: "info" },
    { value: 30, label: "Connect", tone: "warning" },
    { value: 80, label: "Wait", tone: "success" },
  ]}
/>
```

<Canvas of={Stories.SegmentsForTimings} />

## A slim bar in a row

With `labelHidden` and no `showValue`, the bar is only its track: no label row, as tall as `size` makes it, and still named by `label`. Put it in a row of text (a query plan's cost, a quota beside its number) and give it the space with `style={{ flex: 1 }}`; it fills from the reading start in right-to-left text too.

```tsx
<Inline gap="2" align="center">
  <Text size="sm">Seq Scan</Text>
  <ProgressBar label="Cost 1234.5" labelHidden value={45} size="sm" tone="warning" style={{ flex: 1 }} />
  <Text size="sm" tone="muted">cost: 1234.5</Text>
</Inline>
```

## Behaviour and accessibility

- **Role:** `role="progressbar"`, or `role="meter"` with `meter`, named by `label`, with `aria-valuemin`, `aria-valuemax`, `aria-valuenow` and `aria-valuetext` (`valueText` when given). Indeterminate bars have no current value and are `aria-busy`; a meter is never indeterminate.
- **Announcements:** a progress bar is not a live region. To announce completion, say so in the page (a [Notice](?path=/docs/components-feedback-and-display-notice--docs) or a [Toast](?path=/docs/components-overlays-toast--docs)).
- **Contrast:** the fill keeps at least 3:1 against its track in every tone, in light and dark modes.
- **Direction:** fills from the inline start, so from the right in right-to-left text; lit steps do the same.
- **Forced colours:** the fill and lit steps are `Highlight`; each step is outlined.
- **Motion:** the fill eases between values; the indeterminate segment sweeps, and stands still in the middle under reduced motion.

## Theming

`size` sets the thickness: `xs` 2, `sm` 4, `md` 8 and `lg` 12 px. `xs` also sets smaller label and value text and a tighter gap, for dense desktop chrome.

Tokens: `--cy-progress-bar-height-{xs,sm,md,lg}`, `--cy-progress-bar-radius`, `--cy-progress-bar-track` and `--cy-progress-bar-step-gap` (space between steps).

```ts
createTheme({ components: { progressBar: { heightMd: "6px", radius: "2px" } } });
```
