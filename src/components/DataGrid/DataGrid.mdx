# DataGrid

A grid for large results: only the rows and columns in view are rendered, so a hundred thousand rows by fifty columns scroll and move focus as quickly as twenty. Cells can be edited, sorted by several columns, filtered, and opened into row details; columns can be resized, moved and hidden.

<Canvas of={Stories.AHundredThousandRowsByFiftyColumns} />

## When to use

- **Query results and table data**: many rows, many columns, which people scan, sort, filter, resize, select, copy and edit.

**Use something else when:**
- the data is a few dozen rows people read rather than work through: [Table](?path=/docs/components-feedback-and-display-table--docs), a semantic table with row checkboxes
- rows have no columns: [VirtualList](?path=/docs/components-structure-virtuallist--docs)
- one record is edited at a time with many fields: a form in a [Dialog](?path=/docs/components-overlays-dialog--docs)

## Usage

```tsx
import { DataGrid, type DataGridColumn } from "@arshad-shah/cynosure";

const columns: DataGridColumn<Row>[] = fields.map((field) => ({
  key: field.name,
  header: field.name,
  sortable: true,
  resizable: true,
  minWidth: 80,
  align: field.numeric ? "end" : "start",
  cell: (row) => format(row[field.name]),
  cellKind: (row) => (row[field.name] === null ? "null" : field.numeric ? "number" : undefined),
}));

<DataGrid label="Results" columns={columns} rows={rows} getRowId={(row) => row.id} size="sm" />
```

Columns are `width` CSS pixels wide (default 160). `cell` formats a value for display (default: the value as text, objects as JSON); `value` is the raw value that sorting compares and copying writes (default `row[key]`). Set the grid's height with `style={{ blockSize: … }}` or the `height` token.

### Sorting

A `sortable` column's header is a button (a [SortButton](?path=/docs/components-controls-sortbutton--docs) filling the header cell): ascending, descending, then unsorted. The sort is a `TableSort` (`{ key, direction }`), the same as [Table](?path=/docs/components-feedback-and-display-table--docs)'s. Numbers compare as numbers (and dates by time, booleans false first), text in the locale's order, and empty values go last either way. Control it with `sort` and `onSortChange`; with `manualSort` you sort the rows (on a server) and the grid only shows and reports the sort.

### Selection and copying

`selectionMode` is `"none"` (default), `"row"`, `"cell"` or `"range"`. Rows are `selected` (ids, as Table's); cells are `selectedRange`, two corners (`{ anchor, focus }`, each `{ rowId, key }`), so a selection survives sorting and loading more rows. Ctrl/Cmd+C copies the selection as tab-separated text: rows on lines, raw values, and a value holding a tab, a line break or a quote is quoted.

Text inside cells stays selectable: dragging selects text, and a copy with text selected copies that text, the browser's way. Cells are selected by clicking, Shift+click and the keyboard instead, so both work without a mode switch.

### Full values, nulls and numbers

`tooltip` returns the full value of a cell (shown in a [Tooltip](?path=/docs/components-overlays-tooltip--docs) on hover and keyboard focus only while the cell's text is cut short with an ellipsis, and not read to screen readers, since the cell's text already holds it), or nothing. `cellKind` says what a cell holds: `"null"` is muted and italic, `"number"` takes the number colour token. `cellTone` colours a cell with a tone (`accent`, `neutral`, `danger`, `success`, `warning`, `info`), over the kind's colour. `size="sm"` is dense: 28px rows under a 32px header.

### Editing cells

A column with `editable` (`true`, or `(row) => boolean` for some rows) can be edited. Enter or F2 opens the editor on the focused cell, typing a character starts it with that character, and a double-click opens it (Enter on an editable cell edits rather than calling `onAction`). Enter commits and keeps the cell, Tab commits and moves to the next cell (Shift+Tab the previous), Escape cancels, and leaving the field commits it. `onCellEdit(row, key, value)` receives the value: put it in your rows.

`editor` picks the field: `text` (default) gives a string; `number` gives a number, or `null` when emptied, and refuses text that is no number (the field stays open, marked invalid, with `labels.invalidNumber`); `select` edits with a [Select](?path=/docs/components-controls-select--docs) of `options` and commits as soon as one is chosen. The field is named from the column ("Edit Name": `labels.edit`, and the column's `label` when its header is not text).

```tsx
const columns = [
  { key: "name", header: "Name", editable: true },
  { key: "age", header: "Age", editable: true, editor: "number" },
  { key: "city", header: "City", editable: true, editor: "select", options: cities },
];
<DataGrid label="People" columns={columns} rows={rows} getRowId={(p) => p.id}
  onCellEdit={(row, key, value) => update(row.id, { [key]: value })} />
```

### Sorting by several columns

With `multiSort`, Shift+click (or Shift+Enter) on another sortable header adds it as the next key, and again turns it around, then removes it; a plain press sorts by that column alone. Sorted headers show their priority, and say it ("sort 2", `labels.sortRank`); the first key is the header's `aria-sort`. Every key is `sorts` / `defaultSorts` / `onSortsChange` (`TableSort[]`); `onSortChange` still reports the first.

<Canvas of={Stories.ShiftClickSortsByMoreColumns} />

### Filters

A column with `filter` gets a field in a filter row under the header (named "Filter Name", `labels.filter`). `text` keeps rows whose value holds the text, ignoring case; `number` takes a number (`40`) or a comparison (`>30`, `<=40`, `30..40`), and text that is neither filters nothing; a function `(row, query)` keeps the rows it returns true for. The fields' text is `filters` / `defaultFilters` / `onFiltersChange` (by column key); with `manualFilter` you filter the rows (on a server). The fields are reached with Tab and Shift+Tab, outside the grid's arrow keys.

<Canvas of={Stories.FilterRowFiltersByColumn} />

### Column menu: moving and hiding columns

`columnMenu` puts a menu on every header: its button, or Alt+Down, Shift+F10 or the context menu key on the focused header. It sorts the column (when `sortable`), moves it left or right, hides it, and its Columns submenu shows or hides any column; the last shown column cannot be hidden. Focus comes back to the header. The order and the hidden columns are `columnOrder` / `onColumnOrderChange` and `hiddenColumns` / `onHiddenColumnsChange`, controlled or not; columns left out of `columnOrder` follow in their own order. A hidden column neither filters nor sorts the rows, so what shapes them is always on screen; its filter text and sort are kept and apply again when it is shown (with `manualFilter` or `manualSort`, leaving them out is yours to do).

<Canvas of={Stories.ColumnMenuHidesAndReorders} />

### Row details

`renderRowDetails(row)` adds a first column of toggles ("Show details", with `aria-expanded`): a click, Enter or Space opens a panel under the row with that content, and the rows below move down. Each panel is measured, so it can hold anything, and the grid stays virtual. Its controls are reached with Tab from the row; the arrow keys pass over it. The open rows are `expandedRows` / `defaultExpandedRows` / `onExpandedRowsChange`.

<Canvas of={Stories.RowDetailsOpenUnderTheRow} />

### Load more, or pages

`onEndReached` is called once the last rows come into view, once per row count: append the next rows. For pages, put a [Pagination](?path=/docs/components-controls-pagination--docs) under the grid and give the grid one page of rows; paging is not built in.

```tsx
const [page, setPage] = useState(1);
<DataGrid label="Results" columns={columns} rows={rows.slice((page - 1) * 50, page * 50)} getRowId={(r) => r.id} />
<Pagination count={pageCount(rows.length, 50)} page={page} onChange={setPage} />
```

## Behaviour and accessibility

An APG grid (`role="grid"` with rows, column headers and cells) with one tab stop. `aria-rowcount`, `aria-colcount` and each row's and cell's index count every row and column, rendered or not. The focused cell is scrolled into view below the sticky header, and stays rendered while it is scrolled away.

| Key | Does |
| --- | --- |
| Arrows | Move between cells; Left and Right follow the reading direction; Up from the first row reaches the header |
| Home / End | First or last cell of the row |
| Ctrl+Home / Ctrl+End | First or last cell of the grid |
| Page Up / Page Down | A view of rows up or down (Page Up from the first row reaches the header) |
| Enter | On a cell: `onAction` (so does a double-click), or edits an editable cell. On a sortable header: sorts; Shift+Enter adds it with `multiSort`. On a details toggle: opens or closes the details |
| F2, or a character | Edits an editable cell (a character starts the field with it) |
| Enter / Tab / Escape (editing) | Commit and stay / commit and move to the next cell / cancel |
| Alt+Down, Shift+F10 | On a header, with `columnMenu`: opens its menu |
| Alt+Left / Alt+Right | On a resizable header: narrow or widen the column (Shift for a bigger step); announced through `aria-keyshortcuts` |
| Space | Selects the focused row or cell; Ctrl/Cmd+Space toggles a row; Shift+Space extends |
| Shift+arrows | Extend the selection (rows, or a range of cells) |
| Ctrl/Cmd+A | Select every row, or every cell with `range` |
| Ctrl/Cmd+C | Copy the selection as tab-separated text |
| Tab | Leaves the grid |

Clicking a cell selects it (or its row); Ctrl/Cmd+click toggles a row; Shift+click extends. `onRowClick` reports every click or tap on a row. A resizable column's edge is dragged with a mouse, pen or finger; Escape cancels the drag. In right-to-left text the first column is on the right and the edge on a column's left.

## Touch

A finger scrolls the grid in both directions and a tap acts as a click. Rows and the header are at least 44px tall on a coarse pointer, and a column's edge has a 44px hit area.
