# Table

Rows of data with headers. Columns can sort, rows can be selected, and the header can stay in view while the body scrolls.

<Canvas of={Stories.ASemanticTable} />

## When to use

- **Records with the same fields**, read across and compared down: members, invoices, logs.

**Use something else when:**
- there is one record: [DescriptionList](?path=/docs/components-feedback-and-display-descriptionlist--docs)
- items are visual or uneven: [Grid](?path=/docs/components-structure-grid--docs) of [Card](?path=/docs/components-structure-card--docs)s
- the data is nested: [Tree](?path=/docs/components-structure-tree--docs)

## Usage

```tsx
import { Table } from "@arshad-shah/cynosure";

<Table caption="Team members" rows={members} getRowId={(m) => m.id} columns={columns} />
```

A column shows `row[key]` unless it has a `cell` function. `align: "end"` lines numbers up.

## Sorting

Mark columns `sortable` and their headers become buttons (a [SortButton](?path=/docs/components-controls-sortbutton--docs)): ascending, then descending, then the original order. Sorting compares `row[key]` (or `sortValue(row)`): text in the locale's order, numbers as numbers, empty values last. Sort on a server with `manualSort`: the table then shows and reports the sort through `onSortChange` without reordering.

## Selection

`selectable` adds a checkbox to each row (named after the row header, "Select Grace") and a select-all that is mixed when some rows are selected. Selected ids are reported in the rows' own order. Ids that are not in `rows` (another page, or filtered out) stay selected, listed first; the select-all acts on the rows shown.

<Canvas of={Stories.SelectingRows} />

## Tinted columns and cells

A column's `tone` tints its header and cells; a function of the row tints cell by cell, for a heat grid. In markup, `TableCell` and `TableHeaderCell` take `tone`. A tint is colour only and is not read out: say the same in the cell's text.

```tsx
const columns = [
  { key: "zone", header: "Zone" },
  { key: "h9", header: "09:00", tone: (r) => (r.working[9] ? "success" : undefined) },
];
```

## Sticky header

With `stickyHeader` the body scrolls inside the table up to `--cy-table-max-height` and the header stays in view. The scroller is a focusable region named by the caption, so keyboard users can scroll it.

## Written as markup

When the rows are not a list of records (a few fixed rows, cells that differ row by row, a totals row), write them with the compound form instead of `columns` and `rows`. It is the same table, with the same stylesheet and look; `caption`, `captionHidden`, `stickyHeader` and `size` work the same.

```tsx
import { Table, TableBody, TableCell, TableFoot, TableHead, TableHeaderCell, TableRow } from "@arshad-shah/cynosure";

<Table caption="Invoice">
  <TableHead>
    <TableRow>
      <TableHeaderCell>Item</TableHeaderCell>
      <TableHeaderCell align="end" width="8rem">Price</TableHeaderCell>
    </TableRow>
  </TableHead>
  <TableBody>
    {lines.map((line) => (
      <TableRow key={line.id} selected={line.id === chosen}>
        <TableHeaderCell>{line.name}</TableHeaderCell>
        <TableCell align="end">{line.price}</TableCell>
      </TableRow>
    ))}
  </TableBody>
  <TableFoot>
    <TableRow>
      <TableHeaderCell>Total</TableHeaderCell>
      <TableCell align="end">{total}</TableCell>
    </TableRow>
  </TableFoot>
</Table>
```

- `TableHeaderCell` is a column header in `TableHead` and a row header in `TableBody` and `TableFoot` (`scope` overrides it). `width` sizes its column.
- `sort` and `onSort` make a header a [SortButton](?path=/docs/components-controls-sortbutton--docs) with `aria-sort`; you sort the rows. `sort` alone announces a sort made elsewhere.
- `TableRow selected` takes the selected background (body rows). `align`, `colSpan` and `rowSpan` work on both kinds of cell.
- `TableFoot` is set apart by a line above it.
- Every part takes `id`, `data-*`, `className` (layout) and a `ref`. A part used outside its place throws an error naming where it belongs.

## Behaviour and accessibility

- **Semantics:** a native table with a caption; column headers, and a row header per row (the first column, or the one marked `rowHeader`; in the compound form, each `TableHeaderCell` in the body), so screen readers announce context with every cell.
- **Sorting:** sortable headers carry `aria-sort` and contain a button; Enter or Space sorts.
- **Selection:** native checkboxes in the first column; Space toggles; the select-all reports "mixed".
- **Empty:** one cell across all columns says so (`labels.empty`).
- **Touch:** sort buttons have a 44px hit area on touch screens.
- **Contrast:** headers, cells and selected rows keep 4.5:1 in light and dark modes.
- **Attributes:** in both forms, `id`, any `data-*` attribute and the `ref` go to the root element (the bordered wrapper that scrolls).
- **Direction:** columns follow the text direction; end-aligned cells sit at the inline end.

## Theming

Tokens: `--cy-table-header-background`, `--cy-table-selected-background`, `--cy-table-max-height` and `--cy-table-tint-mix` (how much of the tone a tinted cell mixes into the surface, 14%).
