# Tabs

Switches between views of the same thing, such as a document's tree, raw and schema views, while staying on one page. If the options filter or change a value rather than swapping whole panels, use [SegmentedControl](?path=/docs/components-segmentedcontrol--docs).

<Canvas of={Stories.ArrowsSelectSkippingDisabled} />

## When to use

- **Two or more panels of related content** where only one is visible at a time.
- **`variant="line"` (default):** page or panel level navigation with an underline indicator.
- **`variant="soft"`:** compact switchers inside cards, toolbars and side panels.
- **`activation="manual"`:** when showing a panel is expensive (network, large renders), so arrowing past a tab doesn't load it.

**Use something else when:**
- the choice is a setting or filter: [SegmentedControl](?path=/docs/components-segmentedcontrol--docs) or [RadioGroup](?path=/docs/components-radiogroup--docs)
- each option goes to a different page: [Link](?path=/docs/components-link--docs)s in your navigation
- the sections should be readable together: [Stack](?path=/docs/components-stack--docs) with headings

## Usage

```tsx
import { Tab, TabList, TabPanel, Tabs } from "@arshad-shah/cynosure";
import { code, list } from "@arshad-shah/cynosure/icons";

<Tabs defaultValue="tree" onChange={setView}>
  <TabList label="Document views">
    <Tab value="tree" icon={list}>Tree</Tab>
    <Tab value="raw" icon={code}>Raw</Tab>
    <Tab value="schema" disabled>Schema</Tab>
  </TabList>
  <TabPanel value="tree"><Tree /></TabPanel>
  <TabPanel value="raw"><Raw /></TabPanel>
  <TabPanel value="schema"><Schema /></TabPanel>
</Tabs>
```

`TabList` needs a `label`, which names the group for screen readers. Every `Tab` needs a unique `value`. A `TabPanel` with the same value is optional: tabs that drive routed content outside `Tabs` simply don't point at a panel.

## Many tabs

When tabs don't fit, the list scrolls sideways (with no visible scrollbar). Edges that hide tabs fade out, and the selected or focused tab is always scrolled clear of the fade. This also works right to left.

<Canvas of={Stories.OverflowScrollsTheActiveTabIntoView} />

For document tabs, `scrollable` adds chevrons at each end, shown only while there are more tabs that way, and lets a vertical mouse wheel scroll the list sideways. The chevrons are for the pointer: keyboard users move with the arrows, which bring the focused tab into view. `end` puts content after the last tab, outside the tab list, such as a button that opens a new tab; it stays in view when the tabs overflow.

```tsx
<TabList
  label="Open files"
  scrollable
  end={<IconButton icon={plus} label="New query" variant="ghost" size="sm" onClick={newQuery} />}
>
  {files.map((f) => <Tab key={f.id} value={f.id} onClose={() => closeFile(f.id)}>{f.name}</Tab>)}
</TabList>
```

<Canvas of={Stories.ScrollableShowsChevronsTowardMoreTabs} />

## Changing tabs

- **Controlled:** pass `value` and `onChange`. The Tab stop follows selections made from outside.
- **Closing tabs:** when the selected tab is removed, the tab now in its place is selected (or the previous one if it was last), and `onChange` reports it.

<Canvas of={Stories.RemovingTheSelectedTabSelectsTheNextOne} />

## Document tabs

For open files or documents, a Tab with `onClose` gets a close button, and Delete closes the focused tab. A TabList with `onReorder` lets people drag tabs into a new order, or move the focused one with Ctrl+Shift (Cmd+Shift) and the arrows. You hold the list: remove the tab in `onClose` and render the order `onReorder` gives you.

```tsx
<Tabs value={current} onChange={setCurrent}>
  <TabList label="Open files" onReorder={setFiles}>
    {files.map((f) => (
      <Tab key={f} value={f} onClose={() => closeFile(f)}>
        {f}
      </Tab>
    ))}
  </TabList>
</Tabs>
```

<Canvas of={Stories.ReorderWithTheKeyboard} />

A middle-click on a closable tab closes it too, as in browsers and editors.

### Unsaved changes

`dirty` marks a document with unsaved changes: a dot sits where the close button is, and turns into the close button while the tab is hovered or focused. The close button's name says so ("Close b.ts, unsaved changes"), and screen readers hear "Unsaved changes" as the tab's description, after its name. Ask before discarding the changes in your `onClose`.

<Canvas of={Stories.UnsavedTabShowsADotThatBecomesTheCloseButton} />

### Commands on a tab

`contextMenu` gives a tab its own commands, such as Close others or Close to the right, with the items `Menu` takes; `onContextMenuSelect` gets the chosen item's `value`. Right-click, a long press, Shift+F10 or the context menu key opens it. A command that closes the tab moves focus to the tab then selected, as Delete does.

```tsx
<Tab
  value={f}
  onClose={() => closeFile(f)}
  contextMenu={[
    { value: "close", label: "Close", shortcut: ["Delete"] },
    { value: "others", label: "Close others" },
    { value: "right", label: "Close to the right", disabled: isLast },
  ]}
  onContextMenuSelect={(command) => run(command, f)}
>
  {f}
</Tab>
```

## Props

<ArgTypes of={Stories} />

`Tab`: `value`, `icon`, `disabled`, `onClose`, `dirty`, `contextMenu`, `onContextMenuSelect`, `closeLabel`, `children`. The close button is named `labels.close` with the tab's text (a label with markup, such as a badge, is named by the text it shows); give `closeLabel` to name it yourself, such as "Close query 3". `TabList`: `label`, `onReorder`, `scrollable`, `end`. `Tabs` also takes `labels`: `close(name)`, `closeUnsaved(name)`, `unsaved`, `scrollBack`, `scrollForward`, `menu(name)` and `moved(name, position, total)`. `TabPanel`: `value`, `keepMounted` (keep the content mounted while hidden, preserving its state; by default only the selected panel renders its content).

## Behaviour and accessibility

| Input | Result |
| --- | --- |
| <kbd>Tab</kbd> | Focuses the selected tab (one Tab stop), then the panel |
| <kbd>Left</kbd> <kbd>Right</kbd> arrows | Previous / next tab, wrapping, skipping disabled ones (flipped in RTL) |
| <kbd>Home</kbd> <kbd>End</kbd> | First / last tab |
| <kbd>Enter</kbd> <kbd>Space</kbd>, click, tap | Select (the only way to select with `activation="manual"`) |
| <kbd>Delete</kbd> | Close the focused tab (with `onClose`) |
| Middle-click | Close the tab (with `onClose`), without the browser's autoscroll |
| Mouse wheel | Scroll a `scrollable` list sideways |
| <kbd>Shift</kbd> + <kbd>F10</kbd>, context menu key, right-click | Open the tab's `contextMenu` |
| <kbd>Ctrl</kbd> or <kbd>Cmd</kbd> + <kbd>Shift</kbd> + Left / Right | Move the focused tab (with `onReorder`); announced |

- **Roles:** `tablist` (named by `label`), `tab` with `aria-selected` and `aria-controls`, and `tabpanel` labelled by its tab.
- **Hidden panels** stay in the DOM with `hidden`, so `aria-controls` always resolves.
- **Panels are focusable** (`tabIndex=0`), so keyboard users can reach panels without interactive content.
- **Unsaved state** is the tab's description (`aria-describedby` to hidden text), not part of its name, so the name stays the document's for voice control and the panel's label.
- **Forced colors:** the selected tab is outlined with the system highlight colour.

## Touch

Each tab has at least a 24px hit area, and 44px on coarse pointers, without changing its visible size, as do the chevrons of a `scrollable` list. A long press opens a tab's `contextMenu`. The list scrolls with a swipe; to drag a reorderable tab, hold it briefly first.

## Theming

Tokens: `--cy-tabs-dirty` (the unsaved dot, default muted ink), `--cy-tabs-gap`, `--cy-tabs-indicator` (selected colour, default accent), `--cy-tabs-indicator-width` and `--cy-tabs-radius`.

```ts
createTheme({ components: { tabs: { indicator: "#2563eb", indicatorWidth: "3px" } } });
```
