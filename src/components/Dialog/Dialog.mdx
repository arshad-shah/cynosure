# Dialog

A modal window over the page for a task the person must finish or cancel before going on: confirm a destructive action, fill in a short form. The page behind is inert until it closes. In a narrow container (a phone, an extension popup) it becomes a bottom sheet.

<Canvas of={Stories.OpensModalMovesFocusInAndReturnsIt} />

## When to use

- **A decision that blocks the work:** "Discard changes?", "Delete 3 files?".
- **A short, focused form** that belongs to the current page (rename, edit details).

**Use something else when:**
- the content belongs next to a button and can stay open while working: [Popover](?path=/docs/components-overlays-popover--docs)
- it is a list of commands: [Menu](?path=/docs/components-overlays-menu--docs)
- it is a side panel or a phone-style drawer: [Sheet](?path=/docs/components-overlays-sheet--docs)
- it is a message that needs no answer: a Notice or a Toast

## Usage

```tsx
import { Button, Dialog, TextField } from "@arshad-shah/cynosure";

const [open, setOpen] = useState(false);

<Button onClick={() => setOpen(true)}>Edit profile</Button>
<Dialog
  open={open}
  onOpenChange={setOpen}
  title="Edit profile"
  description="Changes are saved to your account."
  actions={
    <>
      <Button onClick={() => setOpen(false)}>Cancel</Button>
      <Button variant="solid" tone="accent" onClick={save}>Save</Button>
    </>
  }
>
  <TextField label="Name" />
</Dialog>
```

Put Cancel first and the main action last. The content scrolls between the title and the actions, so long forms keep both in view.

## Confirmations

With `dismissible={false}` there is no close button and Escape and the backdrop do nothing: the person must pick one of your actions. If the browser closes it anyway (an uncancelable close request), it is shown again. Focus starts on the first action, so put the safe one first.

<Canvas of={Stories.NotDismissible} />

## Without a close button

`closeButton={false}` hides the close button in the header while Escape and the backdrop still close the dialog: for a dialog whose own actions close it (a label picker) or a progress overlay. With `titleHidden` as well, the header takes no room and the title still names the dialog. On a touch screen with no keyboard, the backdrop or an action is the only way out, so keep one.

<Canvas of={Stories.WithoutACloseButtonStillDismisses} />

## Full size

`size="full"` fills the viewport edge to edge, at every width, keeping its content inside the safe areas (notches, the home indicator). Use it for a focus view: one pane or a page preview, shown as large as the screen allows. It has no radius, border or shadow, and fades in without scaling.

When the content names itself (a page preview), set `titleHidden`: the title stays the dialog's accessible name and its `h2` for screen readers, and only the close button shows.

```tsx
<Dialog open={open} onOpenChange={setOpen} size="full" title="Page 3 preview" titleHidden>
  <PagePreview page={3} />
</Dialog>
```

<Canvas of={Stories.FullSizeFillsTheViewport} />

## Content and state

The content is in the DOM only while the dialog is open. It mounts when the dialog opens and unmounts once it has faded out, so every opening starts fresh: fields are back at their defaults, and a closed dialog costs nothing to render.

<Canvas of={Stories.EveryOpeningStartsFresh} />

Set `keepMounted` to keep the content in the DOM while closed. Use it when what the person typed must survive closing, or when the content is expensive to rebuild. Or keep the state outside the dialog, in the component that owns `open`.

```tsx
<Dialog open={open} onOpenChange={setOpen} title="New message" keepMounted>
  <TextArea label="Message" />
</Dialog>
```

## Behaviour and accessibility

| Input | Result |
| --- | --- |
| <kbd>Escape</kbd> | Closes the topmost layer: a Menu, Select or Tooltip inside first, then the dialog |
| <kbd>Tab</kbd>, <kbd>Shift</kbd> + <kbd>Tab</kbd> | Move through the dialog only; the page behind is inert |
| Pointer down on the backdrop | Closes it (only a nested Menu when one is open) |
| Close button | Closes it |
| Android back gesture | Closes it |

- **Focus:** on open, focus moves to the first control in the content, else the first action, else the dialog itself. On close it returns to where it was, usually the button that opened it.
- **Mounting:** closed, the `<dialog>` element is empty, on the server too. The content is rendered in the same render that opens it and removed when the closing transition ends, or at once when there is none (reduced motion). Reopening before the fade has finished keeps the content. With `keepMounted` it always stays.
- **Role:** a native modal `<dialog>`, named by `title` (an `h2`) and described by `description`.
- **Narrow containers:** below 36rem wide, the dialog docks to the bottom edge at full width. `size="full"` fills the container at every width instead.
- **Hidden title:** with `titleHidden` the title is visually hidden (the shared `.cy-visually-hidden`), not removed: it still names the dialog.
- **Isolation:** it never writes to `<html>` or `<body>`. There is no scroll lock; the content uses `overscroll-behavior: contain` so scrolling it does not move the page.
- **Toasts:** inside a [Toaster](?path=/docs/components-overlays-toast--docs), toasts raised while the dialog is open show above it (not under its backdrop), and move back to the page when it closes.
- **Shadow DOM:** works inside shadow roots (extension content scripts).
- **Motion:** a short fade and scale (a slide as a sheet), removed under reduced motion.

## Touch

The close button keeps a 44px hit area on coarse pointers. A tap on the backdrop closes the dialog, and the bottom-sheet actions stay above the home indicator.

## Theming

Tokens: `--cy-dialog-radius`, `--cy-dialog-padding`, `--cy-dialog-width-{sm,md,lg}` and `--cy-dialog-scrim`.

```ts
createTheme({ components: { dialog: { radius: "10px", widthMd: "520px", scrim: "rgb(0 0 0 / 0.6)" } } });
```
