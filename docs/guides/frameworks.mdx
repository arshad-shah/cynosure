# Using with React frameworks

Lumen is a plain React package — it works with every major React framework.
A few framework-specific notes below.

## Next.js (App Router)

1. Import the stylesheets once in `app/globals.css` or at the top of
   `app/layout.tsx`:

   ```tsx
   import '@lumen/tokens/css';
   import '@lumen/tokens/css/dark';
   import '@lumen/react/styles.css';
   ```

2. Mark the file that hosts `ThemeProvider` as a client boundary:

   ```tsx
   // app/providers.tsx
   'use client';
   import { ThemeProvider, TooltipProvider } from '@lumen/react';

   export function Providers({ children }) {
     return (
       <ThemeProvider defaultTheme="system">
         <TooltipProvider>{children}</TooltipProvider>
       </ThemeProvider>
     );
   }
   ```

3. Render the theme init script in `<head>` to avoid a flash on reload:

   ```tsx
   import { getThemeInitScript } from '@lumen/react';

   export default function RootLayout({ children }) {
     return (
       <html lang="en" suppressHydrationWarning>
         <head>
           <script dangerouslySetInnerHTML={{ __html: getThemeInitScript() }} />
         </head>
         <body>
           <Providers>{children}</Providers>
         </body>
       </html>
     );
   }
   ```

`suppressHydrationWarning` on `<html>` silences the benign warning that
arises from the `data-theme` attribute being set by the init script
before React hydrates.

## Remix

- Put the stylesheet imports in `root.tsx` and export them via `links`:

  ```tsx
  import styles from '@lumen/react/styles.css?url';
  import tokens from '@lumen/tokens/css?url';

  export const links = () => [
    { rel: 'stylesheet', href: tokens },
    { rel: 'stylesheet', href: styles },
  ];
  ```

- Wrap `<Outlet />` in the providers as in the Next.js example.

## Vite + React Router

Plain client-side. Follow the [quickstart](?path=/docs/getting-started-quickstart--docs) —
no framework-specific changes.

## TanStack Start

Treat like Next.js. The `'use client'` directive is not required, but the
theme init script + `suppressHydrationWarning` pattern applies.

## Astro (islands only)

Render Lumen inside a React island (`client:load` or `client:idle`). Keep
the island container small so hydration cost stays proportional.

## Tree-shaking

- Use per-component entries in hot paths: `@lumen/react/button`,
  `@lumen/react/combobox`, …
- Root barrel (`@lumen/react`) works fine with modern bundlers (Vite,
  Next.js with Webpack 5 / Turbopack, Rollup) — `sideEffects: false` +
  per-component modules keep tree-shaking effective.

## CSS in SSR

Bundlers pick up the per-component CSS through the ESM imports, so SSR
frameworks emit the right `<link>` tags automatically. If you are building
your own SSR pipeline, collect the generated CSS chunks as you would for
any Vanilla-Extract library.
