# @arshad-shah/cynosure

## 0.4.0

### Minor Changes

- 8f8a2df: New `@arshad-shah/cynosure/astro` adapter, an Astro integration that themes the page on the server: `cynosure({ theme })` adds the product theme as CSS on `:root` and Cynosure's stylesheet to every page, and the saved-mode script inline in `<head>` (`initScript`, default on); `htmlAttributes({ mode, contrast })` gives `<html>` its mode and contrast attributes. See `docs/adapters.md`.
- 8f8a2df: New `Choice`: the row a choice control sits in (the control, its label and description, the whole row clickable), with `strikeWhenChecked` and the tokens `--cy-choice-gap`, `--cy-choice-done-color` and `--cy-choice-strike-width`. Checkbox, Switch and RadioGroup's options are now Choice rows, and each owns its control's look in its own stylesheet: `styles/checkbox.css` holds only the box, the new `styles/switch.css` the switch, `styles/radio-group.css` the radio, and `styles/choice.css` the shared row (it used to be ChoiceBase's stylesheet, now `styles/choice-base.css`). Import Choice's stylesheet with Checkbox's, Switch's or RadioGroup's when you load stylesheets one by one (`styles/manifest.json` lists them). Props, tokens and the look are unchanged; `--cy-checkbox-done-color` and `--cy-checkbox-strike-width` now set the row's done tokens. `ChoiceControlProps` and `ChoiceInput` are exported for building new choice controls.
- 8f8a2df: New `DeviceFrame`: a phone, tablet or browser window drawn in CSS around a screenshot, a video or a live demo. The screen keeps its ratio at any width and clips its content to its corners, `orientation` turns a phone or tablet, and the browser bar shows an optional `url`. It is decoration by default and adds nothing to the accessibility tree; with `label` it is a named figure.
- 8f8a2df: TextField: new `addonStart` prop (controls inside the start of the field, before the input) and `--cy-text-field-numeric` token (the typed text's `font-variant-numeric`). With `type="search"` TextField hides the browser's own search decorations itself. DateField, NumberField and TimeField set `--cy-text-field-numeric: tabular-nums` instead of restyling the input, and SearchField no longer has a stylesheet of its own: `dist/styles/search-field.css` is gone (its rule is in `text-field.css`). ColorField is now a TextField with the swatch button in `addonStart`, and draws its hue and opacity strips through Slider's `trackContent` instead of restyling the slider; it looks and behaves as before.
- 8f8a2df: The root entry exports the types components' props are written in: `IconData`, `IconNode`, `IconMotion`, `IconCategory` and `BrandInfo` (no need to reach into `/icons` for a prop's type), and the layout types `Space`, `PaddingProps`, `Breakpoint`, `BREAKPOINTS`, `LayoutAttributes`, `VisibilityProps` and `GridResponsive`.
- 8f8a2df: New `IconTile`: a Facet icon on a tinted square or circle, for features, settings sections, stats and list items. It has three sizes (the control heights, so it scales with the theme), the six tones, `soft`, `solid` and `outline` variants, and is decorative unless it has a `label`, which makes it an image with that name.
- 8f8a2df: Ten new Facet icons (250 in all) and a Google Play brand mark (98 marks). `calendarDays`, `checkSquare` (a checkbox with a large tick, Lucide's square-check-big), `bookMarked`, `listTree`, `refreshCw` and `qrCode` join their categories. A new `faith` category holds `mosque`, `kaaba`, `crescent` (a crescent with a star) and `prayerBeads` (tasbih). `googleplay` comes from Simple Icons, unchanged. Each has search words in `ICON_KEYWORDS`, and `grid` is now also found by "layout grid".
- 8f8a2df: Layout primitives take what page layouts asked for. `Stack`, `Inline`, `Grid`, `GridItem` and `Container` accept `id`, `role` and `aria-*` in their types (they already passed them on) and `hideBelow` / `hideAbove` (a breakpoint of the window: hidden with CSS, no script). `Grid` `columns` takes a track list for unequal columns (`"2fr 1fr"`). `GridItem` takes `span` and `order` per breakpoint (`{ base: "full", md: 2 }`), measured on the grid's width like its columns, for unequal columns that change with the width and for reordering. `GridItem` and `Stack` take `sticky` and `stickyOffset`. The breakpoint scale is now shared as `BREAKPOINTS`; `GRID_BREAKPOINTS` is the same object.
- 8f8a2df: New `List`: a real `ul` or `ol` with drawn markers (`disc`, `number`, `check`, `icon`, `tile` or `none`), each item a label with an optional description. Numbered lists are ordered lists that count from `start` and suit how-to instructions; `gap`, `divided`, `size` and `tone` adjust the look, and markers follow the reading direction.
- 8f8a2df: New `OptionList` (with `OptionListItem`, `OptionListNote` and `OptionListGroup`): the drop-down list of options under a field, which Select, Combobox and TagInput now all draw with, so their lists are one component instead of three copies. Restyle it with `--cy-option-list-{bg,shadow,max-height,max-width,active-bg}`; Select's `--cy-select-list-*` and `--cy-select-option-active-bg` and Combobox's `--cy-combobox-list-*` and `--cy-combobox-option-active-bg` keep working and set them. TagInput's suggestion list follows `--cy-option-list-*` (it used to read Combobox's tokens). The lists look as before; Select's list now also drops its fade under reduced motion and outlines the active option in forced-colors mode, as Combobox's did. The list classes changed (`cy-select-list`, `cy-select-option…`, `cy-combobox-list`, `cy-combobox-option…` are now `cy-option-list…`).
- 8f8a2df: `Button` takes `square` (as wide as it is tall, no padding, for one icon) and, with `href`, `id` and `linkRef` (the link element). `IconButton` is a `square` Button and takes `flipRtl` (the icon is mirrored in right-to-left text), `iconColor` and `wrapperClassName` (layout of the element around it). `Tooltip` takes `className` for its anchor and `Icon` takes `flipRtl`. IconButton no longer has a stylesheet: `dist/styles/iconbutton.css` is gone (its rules are now Button's `square`).
- 8f8a2df: Printing: closed `Accordion` and `Disclosure` sections print open, and every `TabPanel` prints, in order (unselected panels render their content while the page is printed). The shared `usePrinting()` hook is in `src/foundations/printing.ts`.
- 8f8a2df: New `QRCode`: a QR code drawn as one crisp SVG path from Cynosure's own encoder (versions 1 to 40, levels L, M, Q and H, numeric, alphanumeric or UTF-8 text). `size` takes `sm`, `md`, `lg` or a number of pixels, `quietZone` keeps the light margin scanners need, and `icon` puts a logo in the middle and raises the level to H. It stays dark on light in dark mode, because many phones cannot scan an inverted code. `qrMatrix`, `qrPath` and `qrToSvg` export the encoder for pages without React.
- 8f8a2df: New `Section`: a full-width band of a page with a background (`variant`: `plain`, `surface`, `soft`, `accent`), padding above and below from a space token, and its content in a Container (`size`, or `contained={false}`). `as`, `id`, `aria-labelledby`, `aria-label` and `role` are set on the root, so a Section can be a named region and an in-page link target.
- 8f8a2df: New `SiteFooter`: the bottom of a website. A brand and tagline, link columns as data (`{ title, links }`, in one navigation landmark, each list named by its heading), and a bottom row with `legal` and `social` slots. Columns wrap and the bottom row stacks on narrow screens, and every link has a 44px hit area on touch screens.
- 8f8a2df: New `SiteHeader`: the top bar of a website that scrolls as a document, where `AppShell` (an app frame) does not fit. It has a brand linked home, the site navigation as data (`{ label, href, current? }`, the current one marked `aria-current="page"`), an `actions` slot, a SkipLink before it, and it sticks to the top over a blurred view of the page (`sticky`, default true). Below `collapseBelow` (the header's own width, CSS only) the links move into a menu Sheet opened from a button; Escape closes it and focus returns to the button.
- 8f8a2df: `SkipLink` is shown as an accent outline `Button` link, hidden by the shared `.cy-visually-hidden` until it has focus (still CSS only, so it works without JavaScript), and takes `contained` to show at the corner of the nearest positioned ancestor (AppShell sets it). Restyle the shown link through the `--cy-button-*` tokens; SkipLink's own tokens are `offset` and `radius`.
- 8f8a2df: New `SkipLink`: "Skip to content", hidden until focused and then shown at the window's top-start corner. It is a plain link that works without JavaScript; with it, focus moves to the target (given `tabindex="-1"` when it needs one) without changing the URL, also inside shadow roots. `AppShell` and `SiteHeader` now both use it, so the library has one skip link.
- 8f8a2df: Smaller additions: `Button` `color` (any CSS colour, overriding `tone`; the text on a solid fill is white or black, whichever reads); `Link` `underline` (`always`, `hover` or `none`) and `aria-current`; `ThemeToggle` `storageKey`; `PageHeader` `titleSize` and `Heading` `size="3xl"` (1.4 times 2xl, between PageHeader's md and lg); `EmptyState` `headingLevel={1}` for a page that is the empty state; `Card` `aria-current`, shown with the accent border (`--cy-card-current-border`).
- 8f8a2df: `Stack` takes `direction` (`"column"`, the default, or `"row"`), and its `align` accepts `"baseline"`. `Inline` is now a Stack in a row: it renders Stack with `direction="row"` and keeps its own centring and `wrap` in the new `styles/inline.css` (Inline's rules used to live in `styles/stack.css`). Load both stylesheets for Inline when you import them one by one. Inline's props and look are unchanged.
- 8f8a2df: New `Stat`: a KPI tile on a Card with a label, a value in tabular figures, an optional unit, description and icon, and a `delta` that draws an arrow and the change in a tone and is spoken as "up 12%" (the direction comes from the sign or is given, and the words translate through `labels`). The label and figures are a description list, so they are read together. `href` makes the whole tile one link; `as="li"` keeps a linked stat inside its list item.
- 8f8a2df: `Steps` works as a numbered how-to: `current` is optional. Without it every step is numbered alike, nothing is marked current, no status is read and the list is named "Steps" (`labels.list` still overrides it). A step's own `status` still shows.
- 8f8a2df: Every component now says which stylesheets it needs. `@arshad-shah/cynosure/styles/manifest.json` maps each component to its files, base first, worked out from the source imports at build time (Inline → `stack.css`, Sheet → `dialog.css`, Accordion → `disclosure.css`, IconButton → `tooltip.css`, Button → `loading-dots.css`). The Vite and Astro adapters take `styles: "imports"` to add exactly those stylesheets for the components each module imports. `.cy-visually-hidden` moved from `link.css` to `base.css`, so Steps, Tabs, Calendar, Stat and the others no longer need `link.css`. ColorField now lists `text-field.css` and TagInput `combobox.css`, whose classes they use.
- 8f8a2df: New `VisuallyHidden`: content for screen readers only (`as` `span`, `div`, `p` or a heading), with a `focusable` variant that is shown while something inside it has focus. The shared `.cy-visually-hidden` rule it uses moved from `link.css` to `base.css`, so it no longer depends on loading Link's stylesheet.

### Patch Changes

- 8f8a2df: `Button` no longer cuts off the tails of g, y and p in fonts with deep descenders (Plus Jakarta Sans): the label's box holds the font's whole height. The button's height is unchanged.
- 8f8a2df: `ChoiceBase`'s stylesheet is now `styles/choice-base.css` (it was `styles/choice.css`, which is now the Choice row's), and its class is `cy-choice-base` (was `cy-choice-input`). Update a one-by-one stylesheet import of `choice.css` for ChoiceBase to `choice-base.css`.
- 8f8a2df: `DeviceFrame` fixes from a product page. On a dark page the phone and tablet bezel no longer disappears: it is a dark grey lifted off the page with a lighter rim (3:1 against the page), and still the ink on a light page. Live content on a phone now starts clear of the camera island (below it upright, beside it turned) instead of running under it; a screenshot, video or canvas still fills the screen. The new `safeArea` prop decides for any content.
- 8f8a2df: KeyValueEditor and Checklist no longer reach into the Checkbox and TextField they render: KeyValueEditor lays out its checkbox through a class of its own and hides its file picker with the shared `cy-visually-hidden` class, Checklist finds its focus targets through its own classes, and TagInput's announcer uses `cy-visually-hidden`.
- 8f8a2df: `HiddenValue` hides its input with the shared `.cy-visually-hidden` class from `styles/base.css`, so `styles/hidden-value.css` is gone; drop it from one-by-one stylesheet imports. Behaviour is unchanged.
- 8f8a2df: `Avatar` and `Image` show their picture in server-rendered HTML that is never hydrated (an Astro page without a client directive). Before any script runs the picture shows as the browser has it; on mount an unfinished picture switches to the fallback or placeholder before the first paint, as before. `Image`'s `data-state` has a new first value, `pending`.
- 8f8a2df: Each component styles only its own classes, with no change in look: Pagination, Calendar, CopyButton, QRCode, Dialog, Notice, SideNav, SortableList, Toast and FloatingToolbar place, mirror and colour the Buttons, IconButtons, Icons, Tooltips and Toolbars they render through those components' props and tokens and their own layout classes; Sheet draws its docked panel on its own classes (`.cy-sheet`, `.cy-sheet-panel`, `.cy-sheet-actions`) over the Dialog's frame. Announcer, CopyButton, Field, FileDrop, SideNav's collapsed rail, SortableList, Steps and Table hide text with the shared `.cy-visually-hidden`. SiteHeader's brand and navigation links are `Link`s, drawn as before by the span inside each.
- 8f8a2df: `SegmentedControl`'s internal classes follow its name: `cy-segmented` is `cy-segmented-control`, `cy-segment` is `cy-segmented-control-segment` and `cy-segment-label` is `cy-segmented-control-label`. Restyle through the `--cy-segmented-control-*` tokens; the look is unchanged.
- 8f8a2df: A product palette now reaches everything worked out from it. `createTheme({ palettes })` applies each palette's colours first and derives from them: `accentSoft` is mixed with the palette's own surface (it used Cynosure's), an accent given for one palette re-derives that palette's hover, active, soft, text and on-accent colours, and the high-contrast palettes (`prefers-contrast: more`, `contrast="more"`) start from the product's light and dark palettes instead of falling back to Cynosure's. Colours a patch sets explicitly still win.

## 0.3.0

### Minor Changes

- 953afff: `AppShell` now shares its narrow state, so products no longer repeat the breakpoint. `useAppShell()` returns `{ narrow }` to anything rendered inside the shell (it is `false` on the server, on the first client render and outside a shell), and the new `onNarrowChange` prop tells code outside the shell once per change.
- 953afff: New `AspectRatio` component: a box that keeps a width-to-height ratio at any width, for a video, a map, a chart or an embed. `ratio` takes a number or a CSS ratio such as `"4/3"` (default `16 / 9`) and the height comes from CSS, so nothing is measured. Its children are stretched to the box, images and videos cover it, and `radius` rounds and clips the corners from the radius tokens.
- 953afff: New `Avatar`: a person, team or thing as a picture, falling back to initials worked out from the name (emoji and non-Latin names included) and then to an icon. It has five sizes, circle and square shapes, tones (with `tone="auto"` picking one from the name), a status dot that is spoken with the name, and `decorative` for when the name is written beside it.

  New `AvatarGroup`: overlaps several avatars along the reading direction, gives them one size and sums up the rest as a "+3" avatar that names the hidden people.
- 953afff: New `Breadcrumbs` component: the trail from the top of a site or app to the current page, as a "Breadcrumb" navigation landmark with an ordered list. Pass `items` (`label`, `href`, `onClick`, `icon`); every item but the last is a link or a button, and the last is the current page (`aria-current="page"`). `maxItems` collapses the middle of a long trail into a menu, long names are cut with an ellipsis and the trail wraps in narrow containers.
- 953afff: Button and IconButton now set `aria-current` on the element in both forms, so a link-form button (`href`) can say it is the current page; a link-form button also takes `style` now. Pagination with `getHref` renders the current page as a link with `aria-current="page"` instead of a button. Pagination's `onChange` gets the click event as a second argument, `(page, event)`, so a client-side router can call `event.preventDefault()` on a link press and navigate itself.
- 953afff: `Calendar` gains `markDay`, which marks a day without drawing it: a `tone` tints the cell, `dots` puts up to three coloured dots under the number, and `label` is added to the day's accessible name. The day state passed to `renderDay` and `markDay` has a `weekend` flag that follows the locale. With `renderDay`, a day's height is its own token, `--cy-calendar-content-size`, and defaults to 66px on touch screens (it was 110px), so a six-week month fits a phone while every day stays a 44px target.
- 953afff: `Calendar` can have its month set from outside: `month` (controlled, `YYYY-MM` or any date of the month) and `defaultMonth`, with `onMonthChange` reporting the month asked for. `monthPicker` turns the month heading into a button that opens a panel to jump to any month and year within `min` and `max`. The focused day now always stays inside the month shown.
- 953afff: `Card` takes `edge`: a coloured edge on its inline-start side for a category or status. A tone name uses that tone's colour and any other string is a CSS colour. It follows the reading direction and the card's radius, works with every variant and on link and button cards, and its thickness is the new token `--cy-card-edge-width`. Pair it with text or a Badge, since colour alone carries no meaning for many people.
- 953afff: `Checkbox` has a checklist style: with `strikeWhenChecked`, a checked box strikes through and mutes its label and mutes the description, so a finished task reads as done. The muted label keeps 4.5:1 contrast in light and dark, the strike stays in forced colours, and the new tokens `--cy-checkbox-done-color` and `--cy-checkbox-strike-width` adjust it. Switch and RadioGroup are unchanged.
- 953afff: New `Checklist`: a named list of rows people add, tick, rename in place and remove, such as a task's subtasks. It works controlled (`items`) or uncontrolled (`defaultItems`), moves focus to a sensible control after every change, and has `maxItems`, `reorderable` (drag or keyboard, through SortableList), `disabled`, `readOnly`, two sizes and overridable labels.
- 953afff: New `Container`: the page column. It centres its content, caps its width (`size`: `sm` 640px, `md` 768px, `lg` 1024px by default, `xl` 1280px, or `full` for no cap) and adds side gutters from a space token that never get narrower than a phone's safe area. `paddingBlock`, `center` and `as` (`div`, `main`, `section`, `article`) cover the rest, and the widths are tokens.
- 953afff: The default changed: `Dialog` and `Sheet` no longer keep their content mounted while closed; pass the new `keepMounted` prop to keep the old behaviour. The content now mounts when the dialog opens and unmounts once its closing transition has ended (at once under reduced motion), so every opening starts with fresh state, a closed dialog renders an empty `<dialog>` element (on the server too), and tests can no longer find the content of a closed dialog. Use `keepMounted` for content whose state must survive closing or that is expensive to rebuild. This also applies to what is built on them: `ProgressOverlay`, and the navigation drawer of `AppShell`.
- 953afff: New `Divider`: a line that separates content. It is horizontal by default and fills its container; `orientation="vertical"` stretches it to the height of a row such as an Inline or a footer of links. It can carry a short label in the line (`labelAlign` places it), be `dashed`, take a `strong` tone and add its own `spacing`. It is decorative by default; `decorative={false}` makes it a `role="separator"` named by its label.
- 953afff: `Grid` `columns` also takes a count per breakpoint, `columns={{ base: 1, sm: 2, lg: 4 }}`. The breakpoints (`sm` 30rem, `md` 45rem, `lg` 60rem, `xl` 75rem, exported as `GRID_BREAKPOINTS`) are widths of the grid itself, not the window, so it adapts inside panels, popups and shadow roots. It is CSS only, so server-rendered markup is right on the first paint, and `GridItem` spans are clamped to the columns in effect at each width.
- 953afff: New `Heading` component: a section or page heading whose `level` (the `h1` to `h6` element) is separate from its `size` (`xs` to `2xl`, plus `display` for a hero title), so the page outline stays correct whatever the heading looks like. It has `tone`, `weight`, `align` and `truncate` (one line or a number of lines), uses the display font with a tight line height and balanced wrapping, and has no margins. Each size has a token (`--cy-heading-size-*`) so a product can retune its heading scale.
- b4dc7bf: Icons: `ICON_KEYWORDS` (from `@arshad-shah/cynosure/icons`) maps each Facet icon's name to other words it is found by (`trash`: delete, remove, bin), for galleries and icon pickers. The words are a separate export, so importing an icon does not bring them along.
- 953afff: New `Image` component: a picture that never shifts the layout. `ratio` reserves its space with AspectRatio (or `width` and `height` do), a Skeleton shows while it loads, and a quiet box with the image icon and the `alt` text takes its place when it fails; `placeholder` and `fallback` replace either. It also has `fit`, `position`, `radius`, lazy loading by default, a `caption` that makes a named `figure`, and it notices a picture that had already loaded before React attached.
- 953afff: `Stack`, `Inline` and `Grid` take `padding`, `paddingInline` and `paddingBlock`: space tokens that pad the layout's own box, so a wrapper element is no longer needed for it. The specific prop wins over `padding`, and a nested layout never inherits its parent's padding. Layouts that do not use the new props are unchanged.
- 953afff: Icons in options can be coloured. `Select` and `Combobox` options and `Menu` and `ContextMenu` items take `iconTone` and `iconColor`, with the meaning of Icon's `tone` and `color`. Select keeps the colour in its trigger once the option is chosen. Disabled options show the icon muted, and icons without the new fields look as before.
- 953afff: New `PageHeader` component: the top of a page or a major section, with `breadcrumbs`, an `eyebrow`, the `title` (the header's one heading, at `headingLevel` 1 to 3), a lead `description`, a `meta` row, `actions` and content below. It is built from `Heading` and `Text`. The actions sit at the inline end and move below the text when the header's own width is under 36rem; `size="lg"` with `align="center"` makes a landing page hero, and `divider` draws a bottom border.
- 953afff: New component: Pagination, for moving between the pages of a list or table. It is a navigation landmark of Buttons with previous and next, numbered pages with ellipses, optional first and last controls, a compact "Page 3 of 10" variant for phones, and real links through `getHref`.

  The helpers `pageCount(total, pageSize)` and `pageRange(page, count, siblings, boundaries)` are exported with it.
- 953afff: `SideNav` takes one primary action among its items: `{ kind: "action", id, label, icon, onClick }` (type `NavAction`). In `layout="bar"` it is a round accent button raised above the tab bar, placed where it sits in `items`; in the column it is a full-width accent button and in the rail an icon button. It is a button, never the current page, and does not call `onNavigate`. New tokens: `--cy-side-nav-action-size` and `--cy-side-nav-action-lift`.
- 953afff: New `Text` component: one piece of text in the type scale, for labels, captions, lead paragraphs, helper lines and values. It has presets (`body`, `lead`, `caption`, `eyebrow`, `code`), `size`, `weight`, `tone` and `align` props that map to the font and colour tokens, one-line or multi-line `truncate`, and `numeric` for tabular figures. It renders a `span` by default or the element given in `as`, adds no margins, and is not changed by host CSS.
- b4dc7bf: TimeField can have a picker, and shows the time the way the person's region writes it.
  - `picker` adds a clock button at the end of the field that opens columns rolling under one lens, with a strip of the whole day to jump along (`dayTrack={false}` hides it) and the hours outside `min` and `max` hatched. It is off by default: fields that do not ask for it look as they did.
  - `hourCycle` is `"auto"` by default: `9:30 PM` where AM and PM are used, `21:30` elsewhere, from the browser or from `locale`. `hourCycle={24}` keeps the form every TimeField had before; `hourCycle={12}` fixes the 12-hour form and adds an AM/PM switch to the picker. The value, the limits and what a form receives stay 24-hour `HH:MM`.
  - New labels (`open`, `hours`, `minutes`, `seconds`, `am`, `pm`, `period`, `dayTrack`, `now`) and tokens (`--cy-time-field-row-height`, `-column-width`, `-lens-background`, `-night`, `-day`).
- 953afff: `Toaster` takes `offset`, to keep toasts clear of fixed parts of an app such as a bottom tab bar on a phone. One value (a space step like `"8"` or a CSS length like `"56px"`) moves them in from the top or bottom edge they sit on; `{ block, inline }` also sets the distance from the side. The same distances are the new tokens `--cy-toast-offset-block` and `--cy-toast-offset-inline`, so an app can set them in CSS, for example only below a breakpoint. The toast region now also stays inside the device's safe area (`env(safe-area-inset-*)`) on every side.

### Patch Changes

- 953afff: Theming: `createTheme({ components })` overrides for components with multi-word names (`sideNav`, `timeField`, `segmentedControl`…) are now written as the custom properties their styles read (`--cy-side-nav-…`). Before, they were written with the camelCase name (`--cy-sideNav-…`) and had no effect.

## 0.2.0

### Minor Changes

- 98117b8: SegmentedControl: two controls given the same `name` no longer share one selection. The segments are grouped under a name of the control's own (with ids of its own), and `name` submits the value through a hidden field, so choosing in one control never clears another and a label never points at another control's segment. A form's reset still restores the default. The small size is now exactly as tall as other small controls (26px, was 28px); its segments keep a 24px hit area. In dark mode the active segment is now a visible pill: it used the raised surface, which on dark is as dark as the track, so only the text colour showed which segment was active.

### Patch Changes

- 98117b8: AppShell: text hidden for screen readers (a Table's hidden caption, Kbd and Calendar labels) inside the content or the navigation now scrolls with that area. Before, it escaped the scrolling area and stretched the shell's container, so a full-height shell showed a second, page-level scrollbar beside the content's own.

## 0.1.0

### Minor Changes

- 77703a0: AppShell: `tabs` shows a bottom tab bar on narrow screens. SideNav: `layout="bar"` draws its top-level items as that bar.
- 77703a0: New: Calendar (the APG date grid, with `renderDay` for a month of plans), DateField (typed, stepped or picked) and TimeField (24-hour, read loosely). Dates are `YYYY-MM-DD` strings; the date and time helpers are exported.
